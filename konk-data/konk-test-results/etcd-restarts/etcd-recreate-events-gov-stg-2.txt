----- ROOT CAUSE SUMMARY -----

  Same root cause as us-dev-2:

  1. Karpenter consolidation (WhenEmptyOrUnderutilized) terminates nodes hosting
     etcd pods because the nodes appear underutilized.

  2. etcd container CPU request is only 10m — making any node it lands on a
     consolidation target within the consolidateAfter window (2h here vs 1h in us-dev-2).

  3. No PodDisruptionBudget protects the etcd StatefulSet — Karpenter evicts freely.

  4. EBS volume Multi-Attach error adds delay on each reschedule (volume must fully
     detach from old node before attaching to new node).

  5. The 2h consolidateAfter explains the slower cycle (etcd-2 at 80m, etcd-0 at 20m,
     ~60 min apart vs ~50 min in us-dev-2).

----- RECOMMENDED FIXES (same as us-dev-2) -----

  1. Add PodDisruptionBudget (minAvailable: 2) for bulk-konk-etcd in aggregate namespace.

  2. Increase etcd container CPU requests to >= 200m.
     (linkerd-proxy sidecar already has 100m — total pod needs to be high enough
      that the host node is not flagged as underutilized)

  3. OR add annotation karpenter.sh/do-not-disrupt: "true" to etcd pod template
     as an immediate stopgap.

  Fix must be applied in the konk chart — both gov-stg-2 and us-dev-2 are affected.
