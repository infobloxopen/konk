----- ROOT CAUSE SUMMARY -----

  1. Karpenter consolidation (WhenEmptyOrUnderutilized) terminated node
     nodescaling-node-pool-9jzxd (~52 min ago) and an earlier node (~103 min ago).

  2. etcd pods have no PodDisruptionBudget — Karpenter can evict them freely
     as long as its own disruption budget (nodes: 1 for Underutilized) allows.

  3. Low CPU requests make the host node appear underutilized to Karpenter
     within the consolidateAfter: 1h window, triggering the cycle repeatedly.

  4. EBS volume Multi-Attach error on each eviction adds extra delay before
     the pod can start on the new node.

----- RECOMMENDED FIXES -----

  1. Add PodDisruptionBudget (minAvailable: 2) for bulk-konk-etcd.
  2. Increase CPU requests to >= 200m so nodes don't appear underutilized.
  3. OR add annotation karpenter.sh/do-not-disrupt: "true" to etcd pod template
     as an immediate stopgap.
